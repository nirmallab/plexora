description: "Every shortcut bound in the viewer, and how to see them without leaving the app."

---

Plexora prints a shortcut on the same menu row it is bound to, so what you see
is always what pressing the key does. `mod` below means **Cmd** on macOS and
**Ctrl** on Windows and Linux.

<Callout type="info" title="See them from inside the app">
Help > Keyboard Shortcuts (`mod+/`) lists exactly what is bound on the current
page, grouped by menu. It only lists a shortcut that actually works — if two
things claim the same key, the one that loses is left off the list rather
than shown incorrectly.
</Callout>

## Menu shortcuts

| Shortcut | Action | Menu |
| --- | --- | --- |
| `mod+I` | Import Sample… | File |
| `mod+O` | Samples… | File |
| `mod+,` | Settings… | File |
| `mod+/` | Keyboard Shortcuts | Help |
| `mod+\` | Collapse or expand the sidebar | — |

## Opening a tool

| Shortcut | Tool |
| --- | --- |
| `mod+E` | [Cell Explorer](/docs/plugins/cell-explorer) |
| `mod+B` | [Thresholding](/docs/plugins/thresholding) |
| `mod+K` | [Figure Builder](/docs/plugins/figure-builder) |

A tool only shows a shortcut in its menu row while it applies to the sample
you have open — Cell Explorer needs cell metadata, for instance.

<Callout type="warn" title="ROI and mod+I">
[ROI](/docs/plugins/roi) is also declared with `mod+I`, the same chord as
Import Sample. Import Sample's row is always registered first, so `mod+I`
opens Import Sample and ROI's row in the Tools menu shows no key at all — open
ROI by clicking it in the Tools menu instead.
</Callout>

## On the canvas

These work directly on the image once it has focus (click it once if a text
field was focused), and are not modified chords — a project literally named
"Tonsil" is guarded against firing one by accident while you are typing its
name elsewhere.

| Key | Action |
| --- | --- |
| Arrow keys | Pan |
| `+` / `-` | Zoom in / out |
| `0` | Return to the home view |
| `W` `A` `S` `D` | Pan, once the canvas has focus |
| `T` | Show or hide whatever is drawn over the image — the mask, or a plugin's coloured cells |
| `B` / Page Up | Previous sample in this dataset |
| `N` / Page Down | Next sample in this dataset |

## On a z-stack

The depth strip at the right edge of the image adds these on a stack of
planes.

| Key | Action |
| --- | --- |
| `]` / `[` | Next / previous plane (with Shift, ten; with Alt, the last / first) |
| `V` | Into the 3-D view and back. With the Area tool armed and the pointer on the image, the square is placed there first |
| `Esc` | Disarm the Area tool (on the plane) |

### In the 3-D view

| Key or gesture | Action |
| --- | --- |
| Drag | Turn the stack |
| Shift+drag | Slide the area across the tissue; any cut moves with it |
| Alt+drag, or the middle button | Pan the camera (Shift+drag too, when the whole stack is drawn) |
| `X` `Y` `Z` | With the pointer over it: turn about that axis only; again, or `Esc`, to let go |
| `O` | Show or hide the cut |

The **Area** button on the strip arms a square of a fixed size (300 µm by
default; set it under the strip's gear). Click the image to open that square
in 3-D, drawn at the finest level it allows. A **Cut** takes a side off along
one axis — X, Y or Z; a **Crop** keeps a box along any of them, and **Crop to
area** makes that box the area, fetched finer. **Save area** in the cut panel
keeps the area, the cut and the camera to come back to.

<Callout type="info" title="A tool's own keys">
[ROI](/docs/plugins/roi) and [Figure Builder](/docs/plugins/figure-builder)
each bind extra bare-letter keys of their own — ROI's `V`, `P`, `F` and `R`
switch its drawing tools (its `V` wins over the 3-D view's while ROI is open), `Escape`, `Enter`, `Backspace` and `Delete` edit a
region, and `mod+Z` / `mod+Shift+Z` undo and redo — active only while that
tool's own card is open and its canvas has focus. Each open tool lists its own
keys under the `?` in its card's header.
</Callout>
