Some machines hold your images but are not allowed to run anything. HMS O2's
transfer node (`transfer.rc.hms.harvard.edu`) is the usual example: it exists
to move files, so there is no job to start and nothing to install on it.

A **files-only server** connects to such a machine over SFTP and starts
nothing there. Plexora runs on your computer and reads each image a piece at a
time as you view it, the same way it reads an image at an `https://` or `gs://`
address.

```text
your laptop  ──ssh (SFTP)──▶  transfer node
(Plexora runs here;            (only files are read;
 tiles are cached here)         nothing is started)
```

## Add one

In **Settings → Remote servers**, pick a preset:

- **HMS O2 transfer node**, under *Additional presets*. Asks for your HMS ID
  only.
- **Files on an SSH server**, for any other host. Asks for a username and the
  address.

Press **Save and connect**. Plexora runs your system `ssh`, so your keys,
your `~/.ssh/config` and any login prompt work as they do in a terminal. A
password or a Duo prompt appears in the page.

On O2, Duo is required from outside the HMS network. Set a default Duo method
in your HMS account; HMS needs one for any file-transfer client.

## Open an image from it

In **Import sample** (or on the home page), switch the machine from *Local* to
the server. **Browse** lists its folders — your home folder, `/n/data1`,
`/n/groups`, `/n/scratch` — and a typed path works too: an absolute path, or
one relative to your home folder.

The project records an address such as:

```text
sftp://ajn16@transfer.rc.hms.harvard.edu/n/data1/lab/slide.ome.tif
```

The image list marks such a layer **SFTP**.

## What streams well

The same formats an `https://` address can hold: OME-Zarr, OME-TIFF and other
TIFFs, DICOM, Imaris (`.ims`), PNG and JPEG. A label image at an `sftp://`
address can be used as a mask, and a 3-D Imaris mask is stored in the project
as a label volume.

- **Tiled, pyramidal images stream best.** Each view reads only the tiles it
  shows. A large untiled TIFF has to be read in big pieces and is slow.
- **Everything is cached on this computer.** A second look at the same region
  needs no network, and *Make available offline* (Settings → Web data) keeps a
  whole image.
- **Analysis runs on this computer.** To compute next to the data, use a
  server that runs Plexora instead ([SLURM clusters](/docs/remote/slurm)).
- **Slides that only OpenSlide reads** (`.svs`, `.ndpi`, `.mrxs` and similar)
  need a local copy, as they do over `https://`.

## When it is not connected

A project whose image is on a files-only server opens only while that server
is connected. Otherwise the viewer says so and names the saved server to
connect. Tiles already in the cache still draw.

## If connecting fails

| What you see | What it means |
|---|---|
| *printed text where its SFTP reply should be* | A shell startup file (often `~/.bashrc`) prints on every login. Wrap the `echo` in `if [[ $- == *i* ]]; then … fi`. |
| *accepted the login but does not offer SFTP* | The server has SFTP switched off; ask its administrators. |
| *rejected the login* | Check the username, and the password or key used for it. |
| *Nothing answered at that address* | The machine is unreachable: check the address, the network and any VPN. |
