A dataset groups projects that belong together — a patient cohort, a TMA series, one imaging run — without holding any data of its own. This page covers creating, editing and deleting one, and walking through the samples in it.

## In the UI

**New Dataset…**, beside **Import Sample…** on the Samples page, makes a dataset from a folder of samples, or an empty one to drag projects into (leave the folder blank and press **Create empty dataset**). See [From a folder](#from-a-folder) below. Once a dataset exists:

- **Drag** a project card onto a dataset's folder to put it in; drag it onto **All projects** to take it back out.
- Select several cards (the tick in a card's corner, or ctrl-click and shift-click) and use **Move to…** or **Remove from dataset** in the selection bar to do either in bulk.
<Screenshot src="/screenshots/data/dataset-folder-view.webp" alt="The Samples page with a dataset's folder open, showing the projects inside it" caption="A dataset's folder view: its breadcrumb, the projects filed in it, and New Dataset… and Import Sample… in the header." />

- Open a dataset's folder and use its **Rename** action to rename it, or delete it. If it holds any projects, you are offered **Delete dataset only** (the projects in it move back to the top level; nothing is deleted from disk) alongside **Delete dataset and N samples**, which also removes their data from disk and cannot be undone. A project on a shared, read-only directory cannot be deleted this way and stays at the top level even if you choose the second option.

## From a folder

Choose or drop the folder that holds a cohort in **New Dataset…** and Plexora reads everything under it: images (OME-TIFF, TIFF, OME-Zarr), segmentation masks, cell tables (CSV, Parquet, `.h5ad`), channel lists (`markers.csv`), and runs or stores that are one sample each (Xenium, Visium, SpatialData, DICOM). Every image becomes a project, and each mask and table is matched to the image it belongs to. Files are registered where they are; nothing is copied.

Matching uses the file names and folders, never the file contents alone:

- **Names.** `Sample01.ome.tiff`, `Sample01_mask.tif`, `Sample01_cells.csv` and `sample_1.csv` all name Sample01. Words that describe what a file is rather than which sample it is (`registered`, `mask`, `segmentation`, `cell`, `nuclei`, `cp_masks`, `mesmer`) are ignored when comparing, and numbers compare as numbers.
- **Folders.** A generic name such as `image.ome.tiff` or `cell_mask.tif` takes its sample from the nearest folder that names one, so `Sample01/registered/image.ome.tiff` and `Sample01/segmentation/cell_mask.tif` match, and `segmentation/unmicst-LSP1/cell.ome.tif` is LSP1's. Two `image.ome.tiff` files in different sample folders are two projects.
- **Size.** A mask with a different pixel size from an image is never matched to it.
- **Shared tables.** One `.h5ad` holding every image's cells, with a column that names the image, is attached to every project it names, each reading only its own rows. A CSV cannot be split this way, so a CSV that holds several images' cells is left for you to assign.

Each match has a confidence. A **high** one is filled in. A **medium** one is filled in and the project is marked **Review**. Anything weaker, or a file two projects could equally own, stays in **Unassigned files** with its most likely project suggested. Expand a row to see every file's path and why it was matched; drag an unassigned file onto a row, or use **Assign to…**, to place it. When you assign a file whose name follows a pattern, Plexora offers to apply the same rule to every sample.

The **Status** column reads **Matched**, **Review**, **Missing mask**, **Missing data**, **Image only** or **Already imported** (an image registered earlier is added to the dataset rather than imported twice). **Save spec…** writes the plan as a JSON file that `plexora dataset create NAME --from FILE` reads.

Hidden and temporary files, Plexora's own pyramid copies, pipeline intermediates (probability maps, illumination profiles, QC) and linked folders are skipped. The scan stops at 8 folder levels or 200,000 entries and says so.

The same scan is available from Python and the command line:

```python
import plexora

plan = plexora.plan_dataset("/data/cohort")          # look first
for project in plan["projects"]:
    print(project["name"], project["status"])

cohort = plexora.create_dataset_from_directory("Melanoma Cohort", "/data/cohort")
```

```bash
plexora dataset create "Melanoma Cohort" --scan /data/cohort --dry-run
plexora dataset create "Melanoma Cohort" --scan /data/cohort --dry-run --json > cohort.json
plexora dataset create "Melanoma Cohort" --from cohort.json
```

## In Python

The short form registers a batch of images directly:

```python
import plexora

cohort = plexora.create_dataset("Melanoma Cohort", images=[
    "slide.ome.tif", "slide2.ome.tif",
])
```

The long form takes a spec per project, so each one can carry its own mask, table and columns:

```python
import plexora

cohort = plexora.create_dataset("Melanoma Cohort", projects=[
    {"image": "slide.ome.tif", "segmentation": "slide_mask.tif",
     "data": "cells.csv", "cell_id": "CellID"},
    {"image": "slide2.ome.tif"},
])
```

`create_dataset`, `dataset(name_or_id)` and `list_datasets()` all return a `Dataset`, which supports `len(cohort)`, `for name in cohort` and `"slide" in cohort` over its project names, plus `.add(*names)`, `.remove(*names)`, `.rename(name)`, `.describe(text=None, **meta)` and `.delete()` — each returns the updated dataset except `.delete()`, which returns nothing.

## On the command line

```bash
plexora dataset create "Melanoma Cohort" --images slide.ome.tif slide2.ome.tif
plexora dataset list
plexora dataset show melanoma_cohort
plexora dataset add melanoma_cohort slide3
plexora dataset remove melanoma_cohort slide3      # not deleted, just taken out
plexora dataset rename melanoma_cohort "Melanoma Cohort v2"
plexora dataset delete melanoma_cohort
```

## Moving between samples

Once a project belongs to a dataset, the viewer shows **Previous** and **Next** in the top right corner of the canvas, muted until the pointer is near them, for walking the dataset one sample at a time without losing the channels, colours and open tools you have arranged. The counter between them ("2 / 12") opens a grid of every sample in the dataset to jump straight to one. The order is the order projects were added to the dataset, not however the Samples page happens to be sorted, so walking a cohort does not reshuffle as you go. See [Dataset navigation](/docs/viewer/dataset-navigation).
