`plexora.view()` takes data as well as a name. Each piece — the image, the
segmentation mask, the cell table — may be a path, exactly as it always
could, or a Python object you already have:

```python
import plexora, numpy as np

plexora.view(
    "tonsil",
    image=image_array,       # a numpy array
    segmentation=mask_array, # a numpy label array
    adata=adata,             # a live AnnData
)
```

A path is read from disk the ordinary way. An object is served straight out
of this kernel over Plexora's data-node API, on a loopback port only the
viewer beside it can reach — nothing is written to disk unless you ask for
that (see [Performance](/docs/notebooks/performance)).

## What each argument can be

| Argument | A path is... | An object is... |
|---|---|---|
| `image=` | a whole-slide image file | a `(channel, rows, cols)` numpy array |
| `segmentation=` | a mask file | a 2-D numpy label array |
| `adata=` | an `.h5ad` file | a live AnnData — see [AnnData](/docs/notebooks/anndata) |
| `table=` | a CSV | a pandas or polars DataFrame |
| `sdata=` | — | a live SpatialData object — see [SpatialData](/docs/notebooks/spatialdata) |

Passing a path for one argument and an object for another in the same call
is the common case this is really for — see
[Mixed sources](/docs/notebooks/mixed-sources).

## The function underneath

`plexora.view()` dispatches to
[`register_memory_datasource`](/docs/python-api/datasources/register-memory-datasource)
for anything that is not a plain path. Call it directly when you want to
register data without opening a viewer in the same line, or from a script
that opens the viewer separately.

Calling it again with the same project name **replaces** the snapshots and
re-reads the table's shape, while leaving everything else about the project
— its saved channels, its ROIs, its figures — alone. That is what
[`viewer.refresh(...)`](/docs/notebooks/refreshing) does on your behalf
after you annotate.

## Nothing is written to disk

Level 0 of an image or a mask is your own array, not a copy — only the
coarser pyramid levels the viewer needs are derived from it. A table's
`obs`, `var` and the one matrix you chose are copied into an in-memory
store, because the viewer reads them through a separate process. See
[Performance](/docs/notebooks/performance) for the sizes at which Plexora
starts saying so, and when to reach for `to_disk=True` instead.
